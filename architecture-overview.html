Redesign brief · GraphQL security fuzzer

An LLM fuzzer that reads its own output.

PrediQL keeps v1's real strengths — MAB-guided generation, RAG from live responses, per-node telemetry — and rebuilds everything around them: a first-class dependency graph and objects bucket so chains become possible, security scanning as an evidence-directed iterative loop instead of one shot, per-role provider routing, in-process parallelism under a token budget, resumable step-level execution, and a versioned ground-truth scorer with a dashboard.

PrediQL v1 — as built

  • One 600-line process_node, 8 nonlocals
  • Security = exactly one probe round
  • No graph, no state, no chains (IDOR / UAF absent)
  • One provider, one model, one role
  • Sequential; 80 h for one PokeAPI run
  • Unbudgeted: up to 59M tokens / run
  • Findings = LLM assertion, no oracle
  • Ground truth = two hardcoded DVGA scripts
→

PrediQL — this blueprint

  • Step graph over explicit run state
  • Iterative loop with a convergence criterion
  • Graph + bucket + identities → IDOR / UAF / BFLA
  • Any provider, routed per role
  • Async fan-out, target rate-limit is the ceiling
  • Budget ledger + prompt caching + structured output
  • Deterministic evidence oracle, witness per finding
  • Versioned per-op ground truth → P / R / F1

The API model is the shared substrate every capability reads: normalized schema, a typed dependency graph (Operation / Object nodes; hard & soft edges), a runtime objects bucket, and named identities. The bucket and identities are what v1 lacks entirely — and exactly what chains need.

GraphBuilder has two backends behind one interface: native (PrediQL builds the graph from introspection) or graphqler (import an existing compile). The hard dependency on GraphQLer's YAML is gone — it becomes an option, never a requirement.

Resume replays the journal, recomputes each step's fingerprint, and skips any whose inputs are unchanged and whose outputs exist. Kill a run at hour 60 and the finished steps stay done — nothing in memory is load-bearing.

The single most important behavioral change from v1. Each (operation | chain × probe family) refines its payload from observed evidence until the oracle confirms or a bounded stop. Refinement is evidence-directed, not random — every transition is a small testable rule.

05

Chains: the whole capability v1 lacks

Reuse GraphQLer's proven graph algorithms deliberately — then feed the synthesized chains into the iterative, evidence-grounded loop instead of a one-shot check. All four subclass one ChainStrategy base.

reachability backbone
Topological · SCC
collapse strongly-connected components, topo-sort the DAG, expand each in type-priority order (CREATE < Object < Query < UPDATE < DELETE). Self-sufficient chains that run on an empty bucket.
broken access control
IDOR · cross-user replay
CREATE under primary, remaining steps under secondary. Finding requires the differential — primary-can ∧ secondary-should-not-but-can — not a label. Non-dispatchable object nodes filtered.
phantom resource
UAF · quadruple (c,o,d,r)
CREATE produces object o, DELETE consumes o, Query consumes o → run c→d→r. Finding when the post-delete read returns non-null. DELETE gated behind --allow-destructive.
generalized · new
BFLA & second-order
any state-precondition vuln is a chain: BFLA = low-priv identity performs a high-priv op; second-order = inject on write, observe on read. New classes subclass the base — no engine change.
critical high medium low oracle-confirmed differential control
06

Token efficiency, ranked by impact

The largest lever v1 threw away: it took a provider argument and discarded it, ran one model for every role, re-rendered the schema into every prompt, and parsed prose with regex. Seven changes, roughly ordered by expected saving.

01

Role routing

Cheap/fast generator; strong model only for the ambiguous residual (unknown action labels, ambiguous findings). The dominant coverage-stage spend moves to the cheapest capable model.

fixes P6 · _resolve_chat_url_model ignored its arg
02

Structured output

JSON-schema candidates instead of markdown + regex. A parse failure no longer wastes a whole call, and one call returns k candidates — v1 hardcoded n_variants=1.

fixes P5 parse-failure waste
03

Prompt prefix caching

Static preamble + per-op schema first (cached), variable RAG last. v1 re-rendered the schema — its largest repeated payload — every arm, every round.

cache hits across arms & rounds
04

Budget ledger

Hard --budget-usd / per-stage caps. When an op won't cover under its slice it degrades then yields. The 99%-for-32% GraphQLZero outcome becomes impossible.

fixes P5 runaway
05

Oracle-first adjudication

Deterministic oracle runs free; the LLM judge sees only the ambiguous residual, batched. v1 ran the LLM detector per response × per class — 27,166 s on one PokeAPI run.

fixes P4 & its cost
06

Incremental index

Append-only embedding index keyed by response hash; re-embed only new responses. v1 rebuilt the FAISS index from scratch after every round.

removes per-round rebuild
07

Terminal "covered" state

Once an op is covered + validated, it's a terminal journal state — not a re-checked condition re-entered each round.

stops redundant generation

Measured, not asserted. Every LLM call meters through the gateway into the budget ledger; the report emits the same per-stage token/cost decomposition RESULTS.md already has — so the reduction is demonstrable on the same targets.

07

Ground truth & scoring

The AutoSec gtpov pattern ported to GraphQL: a versioned, certifiable, per-target file with a per-operation contract, and a score step that emits P / R / F1 — replacing the two hardcoded DVGA scripts, and adding what v1 never had: negative ground truth.

per-operation contract
operation: systemDiagnostics
vulnerable: true
classes:
  - id: os_command_injection
    severity: critical
    evidence_kind: sentinel
    witness_hint: "/etc/passwd root:x:0:0"
    preconditions: [username, password]  # multi-field gate
# — NEGATIVE truth: precision needs it —
operation: systemHealth
vulnerable: false
evidence strength ladder
sentinelinjected marker / file content appears
differentialdiffers from benign control, payload-attributable
latencyexceeds baseline median + k·MAD, reconfirmed
disclosurevisible to an identity that should not see it
reflectionechoed verbatim — weakest; prefer stronger

Path traversal labeled sentinel only scores a true positive if the oracle found actual file content — the exact over-count GraphQLer's reflection-only detector suffers.

recall
Coverage-conditioned
TP / (TP + FN restricted to covered ops) — separates "never reached it" from "reached it, missed it".
precision
Negative contracts
a confirmed finding on a vulnerable:false op is a counted FP — not inferred by a heuristic.
two matrices
Confirmed vs potential
see the precision cost of trusting potentials as a number — v1's 2,130 problem, quantified.
certify · replay
Content-hashed
editing a contract drops the badge until re-certified · score --run re-scores finished runs, no re-run.

Build it without stranding v1

A strangler migration, not a big-bang rewrite: build the engine skeleton, port v1's proven pieces (MAB, RAG, sub-schema extractor, coverage model, cost accounting) behind the new interfaces, and prove equivalence before retiring anything. Each phase ships something runnable.

Parity gate — don't retire v1 on faith. Before deprecation, PrediQL must reproduce v1's node-coverage within ±5 pp on the shared RESULTS.md corpus at materially lower token cost, reported with the same per-stage decomposition. The GraphQLZero × LLaMA row — 15M tokens for 32% coverage — is the headline regression the budget ledger must forbid.

Ported, not rebuilt. Thompson MAB & arm space · delta-coverage as field-path sets · the sub-schema extractor (already trims big graphs for prompts) · success / negative-success checks · token accounting · introspection. The shape is what gets rewritten — the 600-line process_node, the mutated Config singleton, regex-parsed prose, the one-shot Stage 3.
